# 阶段验收与故障注入

每个阶段先实际启动桌面程序，再执行构建和测试。前端浏览器 smoke test 不能代替桌面启动验收；Node 的 SQLite schema 检查不能代替 Rust service 集成测试。

## Phase 1

- `npm run doctor` 开发工具检查。
- `npm run tauri dev` 实际开窗，读取 Rust 返回的数据库版本和系统路径。
- 关闭后再启动，schema 仍为 v1，设置保留；再次双击只激活已有实例。
- `npm run build` strict TypeScript 与生产前端构建。
- `npm test` 启动界面与实际 SQLite schema 约束。
- `npm run test:rust` 迁移重复执行、中文路径、数据库损坏、未来版本、校验和改变、未知数据库保护。
- 改坏临时测试库时界面显示停止状态，原文件字节不被删除或替换。

## Phase 2–3

- 用临时根目录中三个独立文件验证001、002、003；注入测试时钟验证跨日001。
- 0字节、持续写入、2秒中再次改变、复制后短暂停顿、被占用、只读目录均验证。
- 中文/空格/括号路径、不同扩展名大小写、子目录、符号链接越界。
- 同名目标与竞态创建目标不能被覆盖；根目录失联不批量标记 missing。

## Phase 5–6 核心自动测试（必须新增真实 Rust service 测试）

| 场景 | 期望 |
|---|---|
| 0→1；3→4 | 实际文件名、数据库 count/path、use_event 一致 |
| 同素材5个并发请求 | 仅一个受理；其他立即返回忙或过期，不能排队累加 |
| 同request_id再次提交 | 原结果，事件和计数不能重复 |
| 改名目标已存在 | 两个原文件字节不变，count不变 |
| 原文件不存在 | 保留记录与历史，禁止count增加 |
| 改名权限/占用失败 | count不变，中文提示，日志保留详情 |
| journal写入失败 | 不改名 |
| 改名后事务失败 | 安全反向改名；回滚受阻则暂停并保留日志 |
| commit后IPC响应丢失 | 再查同请求得到成功，不能+2 |
| 崩溃在pending提交前/后、rename前/后、数据库commit前/后 | 按恢复表重启，每个点再中断恢复一次，结果幂等 |
| old/new两文件、两文件都失踪、指纹变动 | needs_review/missing，不能猜测覆盖 |
| 手动改名的唯一身份/重复内容 | 唯一可确认更新；重复映射需要人工确认 |
| WAL备份与7份轮替 | Backup API，quick_check成功，素材未复制 |

后端用可注入 Clock、Filesystem、Repository/FaultInjector，在真实临时 SQLite 与临时文件夹验证上述场景；生产实现不加入“假成功”分支。前端测试点击锁与陈旧响应，后端测试跨窗口/进程保护。

## Phase 7–8

- 1000/5000/10000素材：记录首屏、查询p95、滚动DOM数、内存、缩略图并发和缓存命中率。
- 不能以浏览器模拟数据替代实际桌面文件I/O测试；真实视频与数据库压力fixture分开测。
- Windows干净机器与Apple Silicon Mac真实安装：离线开窗，无Node/Python/Rust环境。
- 将3段真实视频放入根目录，默认003/002/001，对003连续点击3次，检查硬盘和数据库均为3次，重启后不变。
- 不支持编码与损坏视频分别测试 fallback；AVI/MKV 入库支持不等于所有编码能内置播放。
- macOS签名/notarization与Windows签名作为正式分发验收；测试安装包未签名必须明确标记。
